# Стратегические цели

Цели ниже — то, зачем владелец держит проект. Они не равны списку ближайших задач и не разрешают открывать следующую волну самим.

## 1. Честный личный учёт без брокера

Инвестор вручную ведёт один или несколько портфелей так, чтобы себестоимость, кэш, комиссии, налоги (когда модель готова) и доход сходились с журналом. Пополнение не маскируется под результат. Частичная оценка не маскируется под полную. Это ближайшая продуктовая цель с 2026-11-19.

## 2. Понятный кабинет

Пять главных мест: обзор, портфель, доходы, решения, рынок. Русский язык инвестора. Пустые и неизвестные состояния видны. OWNER-диагностика не торчит в первом экране. Вид, который владелец отверг 2026-10-30, целью не является, даже если PR уже в main.

## 3. Совет, который можно проверить

Daily Decision, память решения и Shadow должны показывать цепочку: почему возник сигнал, что решили, что исполнилось, какой след оставлен. Уверенность модели не обещает доходность. Совпадение с реальной покупкой не становится причинностью без подтверждения человека.

## 4. Исследование, которое не врёт

Walk-forward, версии датасета, отдельная память решений, candidate → champion. Отрицательный результат кампании V4 (нет прироста OOS) — успех честности, не провал процесса. Новая модель не становится боевой, пока её не сравнили и явно не повысили.

## 5. Право на реальные деньги ещё не цель текущего этапа

Дальняя цель документов — заслужить исполнение. Путь длинный и сейчас закрыт: нет автономной торговли, нет брокерского API, нет Dataset V5. Цель «когда-нибудь уметь исполнять» не превращается в задачу спринта.

## Как цель становится работой

1. Владелец называет волну или узкую задачу.
2. Один этап — один PR, отдельный worktree.
3. Финансовый смысл проверяется строже, чем отступ в вёрстке.
4. Merge функционального PR — только по явному разрешению.
5. Статус в Vault не заменяет GitHub.
