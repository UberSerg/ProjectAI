# KRK-RISK-0005 — PR #97 конфликтует с журналом контекста

## Суть

PR #97 (Agent 00, документация и аудит) редактирует Master Context и на снимке 23 ноября OPEN. Голова, названная в текущем состоянии: `26b3c67eb0816e56e507ec97465b7c93aae68357`. Более ранние абзацы помнят другую голову `1078eeca66ae0fddf0e6e4d0547b8e2d329e1c8a`. Файл на main уже содержит решения 30 октября, 19 и 23 ноября.

## Как проявляется

Merge без ручного сведения может затереть отказ по журналу, политику CI, локальный Vault или продублировать старый baseline. В самом main baseline 28 октября уже продублирован после вставки позиции 29 октября. Это редактура, не второй инцидент.

## Почему опасно

Контекст — источник статуса. Потеря абзаца выглядит как отмена решения Owner.

## Причина

Несколько авторов писали один файл. Прямые docs-коммиты в main обгоняли ветку #97.

## Как должно работать

#97 вбирает main, сохраняет все датированные решения, не стирает журнал, не объявляет открытые PR смерженными.

## Предлагаемое исправление

Неразрушающее сведение до любого merge #97. Не чинить это по дороге в финансовом PR.

## Критерии закрытия

Diff #97 против актуального main не удаляет решения 28–30 октября и 19–23 ноября. Либо PR закрыт без merge с записанной причиной. Живой GitHub-статус перед действием перепроверить: эта карточка опирается на снимок.
