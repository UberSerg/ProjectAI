# KRK-BUG-0004 — Оставшиеся гонки загрузки (PR C)

## Суть

PR #86 закрыл часть устаревшего async для Decision Memory и PortfolioContext. Объём PR C описывает соседние экраны, где поздний ответ всё ещё может затереть текущее состояние. Отдельного PR C нет.

## Как проявляется

По спецификации 28 октября, не по свежему баг-репорту:

- QuotesExplorer: старый запрос свечей или обзора очищает loading/error или подменяет ряд текущего инструмента.
- InstrumentsPage: старый каталог затирает items/total; прерванный sync-status выглядит как честный NONE.
- `clampRange` не всегда оставляет интервал внутри доступной истории на краях и перевёрнутых датах.
- PortfolioPage вызывает `createPersonalPortfolio()` и затем `refreshList()` мимо защищённого пути #86. Успешный POST и упавший GET оставляют портфель потерянным в UI. Повторный POST ради починки GET запрещён.

## Почему опасно

Человек видит чужой график, пустой каталог или думает, что портфель не создан, и создаёт второй. Финансовая формула при этом может быть верной, поэтому приоритет P2, ниже целостности проводок.

## Причина

Защита #86 точечная. Спека PR C прямо говорит: контекст уже изменён, его не откатывать, а доиспользовать.

## Как должно работать

Ответ применяется только если он ещё про текущий ключ запроса. Отмена не притворяется бизнес-состоянием NONE. Создание портфеля идёт через защищённый путь.

## Предлагаемое исправление

Отдельный PR после PR B, как просил Owner. Маленький diff, тесты на порядок ответов и unmount.

## Критерии закрытия

Тесты из пяти пунктов приёмки PR C зелёные, PR смержен, семантика денег не изменилась.
