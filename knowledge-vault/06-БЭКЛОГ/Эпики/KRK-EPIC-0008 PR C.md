# KRK-EPIC-0008 — PR C

## Зачем

Поздний ответ сети не должен стирать текущий график, каталог или факт, что портфель уже создан.

## Текущее состояние

#86 уже защитил Decision Memory и основной путь PortfolioContext. Это `partial`, и оно в main. Остаток спецификации PR C не начат: котировки, каталог, clamp диапазона, прямой create на странице портфеля. Отдельного PR нет. Статус `approved` в том же смысле, что у B: очередь названа, работа не открыта. B идёт раньше.

## Желаемый результат

Быстрое переключение инструмента, диапазона, фильтра и страницы не показывает чужие данные. Прерванный запрос не становится состоянием NONE. Успешное создание портфеля не требует второго POST, если список не дочитался.

## Техническая реализация

Игнорировать ответ, если ключ запроса устарел или компонент размонтирован. Повторить приём #86 на оставшемся create, не откатывая #86. Тесты Vitest на порядок ответов. Финансовые формулы не менять.

## Зависимости

Порядок Owner: после PR B. Технически куски независимы, но смешивать PR запрещено спецификацией («держать B и C маленькими и разными»).

## Критерии готовности

Пять групп проверок из раздела PR C в Master Context. Сборка frontend на финальном SHA. Нет повторного POST. Нет изменения семантики денег.
