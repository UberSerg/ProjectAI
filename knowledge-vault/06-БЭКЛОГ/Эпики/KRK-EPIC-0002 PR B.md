# KRK-EPIC-0002 — PR B

## Зачем

Preview, комиссия и проведённая строка журнала должны быть одной операцией. Иначе личный ledger нельзя брать за основание себестоимости.

## Текущее состояние

Объём записан 2026-10-28 как PLANNED и на 2026-11-23 PR не имеет. Статус `approved` здесь значит: Owner назвал это следующим объёмом и запретил создавать PR только из любопытства реестра. Кода нет. `implementation_status: none`.

## Желаемый результат

Одно количество до POST. Дата не сбрасывается при смене типа. Новое открытие формы чистое. Повтор того же запроса возвращает исходную строку и исходную комиссию. Чужой payload с тем же ключом даёт 409. Нет второй проводки.

## Техническая реализация

Узкий PR по путям из Master Context: модалка личного портфеля, `personal_portfolio_service`, `broker_fee_service`, тесты портфеля и комиссий. Сравнение идёт по стабильному исходному запросу, не по комиссии, пересчитанной из сегодняшнего тарифа.

## Зависимости

Нет зависимости от #100. Стоит раньше PR C и раньше эпика себестоимости. Не зависит от сети.

## Критерии готовности

Регрессия lots=2 / units=5 / lot_size=10 не даёт 500 ₽ в preview и 2 000 ₽ в журнале. Смена типа хранит время. Повтор упавшего запроса хранит ключ. Смена тарифа между одинаковыми повторами не плодит строку. Существующий ledger не переписан. CI на финальном SHA по правилам финансового PR.
