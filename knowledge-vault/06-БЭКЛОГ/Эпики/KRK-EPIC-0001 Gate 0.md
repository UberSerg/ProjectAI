# KRK-EPIC-0001 — Gate 0

## Зачем

Нельзя сравнивать Kraken со Snowball и нельзя верить скриншотам, пока не доказано, что браузер смотрит в нужный исходник, а человек может завести портфель и операцию без технических id.

## Текущее состояние

Roadmap от 2026-11-19 описывает волну и прямо говорит: это не старт реализации. В main уже есть хаб с честной оценкой (#91), Design System (#98), путь инвестора (#84). Журнал V4 не принят. Mount не проверен. PR B не начат. Пять «главных» направлений навигации из roadmap в продукт не собирались отдельным PR.

`implementation_status: partial` означает только уже смерженные куски, не выполнение Gate 0.

## Желаемый результат

Незнакомый человек создаёт портфель, вручную вводит операцию, видит позиции и качество оценки. Демо-сценарий переживает обновление страницы. Пропуск цены не выглядит нулём. Клавиатура и узкий экран не разваливают основной сценарий.

## Техническая реализация

Сначала диагностика mount и смотр. Потом, отдельными PR, дыры, которые смотр найдёт. Навигация Overview / Portfolio / Income / Decisions / Market — только если Owner подтвердит эту волну. OWNER-инструменты уходят во вторичную навигацию, не удаляются.

## Зависимости

KRK-TASK-0001 до смотра. PR B (KRK-EPIC-0002) до того, как ручные штуки и комиссии считаются доверенными. Журнал V4.1 не подменяет Gate 0.

## Критерии готовности

- Известен SHA, который отдаёт frontend.
- Сценарий: кэш, покупка, продажа, дивиденд, обновление страницы, перезапуск — на DEMO, без личного ledger Owner в отчёте.
- Нет скрытого расхождения worktree.
- Приёмка Owner на этом сценарии, не только CI.

## Риски

Ложный смотр при старом mount. Случайный `down -v`. Подмена Gate 0 большим редизайном.
