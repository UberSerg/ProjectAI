# Как вести задачи

Источник исполнения — GitHub Issues и PR. Vault хранит человеческий указатель и не объявляет задачу слитой. Master Context хранит проверенный статус проекта. Если они разошлись, верьте GitHub для кода и контексту для решения владельца, затем поправьте указатель.

## Статусы, которые нельзя склеивать

Идея, предложение, разрешено, готово к работе, в работе, заблокировано, на ревью, готово к взгляду владельца, принято, влито, в релизе, отложено, отменено. «Написано» не равно «влито». «Влито» не равно «принято». «В плане roadmap» не равно «в работе».

PR B и PR C с 2026-10-28 остаются планом, пока по ним нет ветки, открытой по поручению. Упоминание в контексте не поручение создать PR.

## Как резать

Большую волну делят до старта. Gate 0 не включает XIRR и P&L решения. Финансовая цепочка идёт последовательно. Вёрстка может идти рядом, если не трогает те же строки. Новую модель в UX-задачу не добавляют.

У задачи есть: зачем, что правда сейчас, какой результат, что сознательно вне объёма, от чего зависит, как поймём готовность, какой риск. Карточка без запрета раздувается.

## Приоритет спора

1. Текущее явное поручение владельца.
2. Текущий `main` и проверенный PR.
3. Правила архитектуры и протокол.
4. Старые документы и старые чаты.

Если код противоречит архитектурному запрету, работу останавливают и спрашивают. Молча «починить запрет» нельзя.
