# Исследования


## Визуальный ориентир

![Исследования](../../_assets/illustrations/research-evidence.jpg)

*Evidence research-only. Иллюстрация Vault; не скриншот приёмки.*

**aliases:** Research  
**Baseline:** `origin/main` `73c2e25e6aed323174b11dea4514946d5897f54b`  
**Пакеты:** `research_lab`, `research_cycle`, `research_evidence`  
**См.:** [[Датасет]], [[Research Evidence Engine]], [[Исторический симулятор]], [[Прогноз]]

## 1. Назначение

Проверять идеи на истории и собирать доказательства так, чтобы отчёт нельзя было перепутать с боевой моделью, личной книгой или Shadow.

## 2. Какую задачу решает

Держит четыре разных утверждения отдельно: «признаков стало больше», «есть хронологический OOS», «есть экономический прогон», «есть наблюдения после уже показанных решений».

## 3. Как работает простыми словами

Исследователь собирает датасет, гоняет модель только вперёд по времени, смотрит, помогает ли группа признаков, и прогоняет длинные позиции с комиссией-допущением. Рядом, отдельным блоком, лежат исходы уже выданных решений. Общей «точности Kraken» экран не считает.

## 4. Архитектура

Три пакета и экраны:

| Кусок | Роль | HTTP / UI |
|---|---|---|
| `research_lab` | лаборатория сравнения | `/api/v1/research-lab`, `/research` |
| `research_cycle` | дневной цикл EOD для живого контура | `/api/v1/research-cycle` |
| `research_evidence` | артефакты доказательств V3/V4 | `/api/v1/research/evidence`, `/research/evidence` |

Дополнительные маршруты: `/research-hub`, `/research/advanced`, `/research/compare`, `/research/diagnostics`, `/research/prospective-models`, `/research/:runId`. `[GITHUB_VERIFIED]` `App.tsx`.

Документ Evidence Engine: research-only, без повышения модели, без мутации Shadow, без переписывания личной памяти, без брокерских заявок. Техническая версия в том тексте остаётся `1.0.0`. Фраза «нет Kraken 1.04» внутри документа устарела относительно manifest: запись 1.04 на этом SHA как раз про research/evidence. `[GITHUB_VERIFIED]` оба текста.

Тяжёлые прогоны документ отправляет в существующий Workflow / Celery, без новой очереди.

## 5. Поток данных

```text
Dataset V3 или V4
  → хронологический OOS (расширяющиеся фолды, purge метки)
  → ablation четырёх масок признаков
  → экономический симулятор исследовательского портфеля
  → Historical Evidence

Forward Outcomes + память решений
  → Prospective Evidence
```

Идентичность эксперимента — SHA-256 канонического JSON. Время запуска в смысл не входит. Несовпадение контракта V3/V4 даёт `FAIR_CONTRACT_FAIL`, и шаги модели не запускаются. `[GITHUB_VERIFIED]`

## 6. Что уже реализовано (только подтверждённое)

- Код `research_evidence`: oos, ablation, economics, prospective, campaign-*. `[GITHUB_VERIFIED]` список файлов.
- Эндпоинты, названные документом: overview, run, карточка эксперимента, economics, prospective. Overview отдаёт агрегаты, не свалку строк прогноза. `[GITHUB_VERIFIED]` документ; сверка каждой функции роутера построчно не делалась.
- Метрики регрессии и ранжирования разведены. У ранга нет MAE/RMSE/R². Ранг не подписывается как ожидаемая доходность. `[GITHUB_VERIFIED]`
- Ablation: BASE, BASE+фундаментал, BASE+события, V4 FULL. Пропуск остаётся NaN. Мало дат → `INSUFFICIENT`, без выдуманной p-value и без вердикта «V4 победил». `[GITHUB_VERIFIED]`
- Экономика: long-only, без плеча, OPEN следующей сессии, дивиденды исключены, бенчмарк — равный вес допустимой вселенной на тех же датах. `[GITHUB_VERIFIED]`
- UI-плашка RESEARCH ONLY; запрет бейджей LIVE READY / PRODUCTION READY / AUTO TRADE. `[GITHUB_VERIFIED]` документ.
- Manifest 1.04: каноническая кампания не показала улучшения V4 против BASE. `[GITHUB_VERIFIED]` текст заметки, не повторный расчёт.
- Daily Research Cycle описан в документе Shadow как идемпотентный шаг Forward + продвижение Shadow, когда данные готовы. `[GITHUB_VERIFIED]`

## 7. Что частично реализовано

- Покрытие дивидендов неполное, поэтому экономика остаётся price return. `[GITHUB_VERIFIED]`
- Банки и часть фундаментала ограничены поддержкой FNS RAS. `[GITHUB_VERIFIED]`
- Исторический делистинговый охват документ называет partial.
- Дробные веса и отсутствие модели проскальзывания ликвидности документ называет ограничением.
- Перспективная выборка может быть `INSUFFICIENT_SAMPLE`.

## 8. Что пока исследуется

Любая следующая спецификация после V4, включая Dataset V5, в Evidence Engine и в Master Context не разрешена. Открытый PR #58 (дивиденды / календарь / вселенная) по снимку Master Context остаётся независимым и не влитым. Live API не перепроверялся.

## 9. Технические ограничения

- Активная спецификация датасета не переключается сравнением.
- `persist_registry` для этого контура ложен. Candidate V2 документ не создаёт.
- Случайное разбиение и Optuna запрещены. Гиперпараметры заморожены.
- Стоимости 0/10/30/50 б.п. не являются тарифом Сбера.
- Историческое и перспективное нельзя усреднить в один скор.
- Окно, которое уже смотрели, нельзя называть девственным holdout, если репозиторий это не доказывает. Формулировка документа: CHRONOLOGICAL OOS RESEARCH.

## 10. Известные ошибки

Внутренние статусы документов («OPEN / NOT MERGED», «продукт всё ещё 1.03 / нет 1.04») не совпадают с тем, что файлы и manifest 1.04/1.05 лежат на `73c2e25`. Это ошибка актуальности текста, не опровержение запрета на продакшен-активацию. Активация по коду по-прежнему `PIT_DAILY_CORE_ACTIVE_VERSION = 1`.

## 11. Основные пользовательские сценарии

- OWNER открывает «Доказательства» и видит два блока и карточку ограничений.
- Сравнивает эксперимент в лаборатории.
- Не использует эти экраны как сигнал к сделке в личной книге.
- USER/OWNER здесь уровень показа, не отдельная учётная запись. Документ просит не раздавать исследовательские диагностические эндпоинты шире, чем UI-роль. Полноценного IAM нет.

## 13. История развития

Фундамент V4 описан отдельным документом и присутствует кодом `v4_enrichment.py` и `compare_v3_v4.py`. Evidence Engine надстроен сверху. Продуктовая запись 1.04 (2026-10-04) фиксирует результат кампании как baseline. Технический тег остаётся `v1.0.0`.

## 14. Потенциальное развитие

Документ V4 перечисляет, что потребовалось бы до любого будущего повышения: замороженный контракт, walk-forward, честное решение по total return, затем Shadow, сигнал и человеческое подтверждение. Это список условий, не план спринта. `PROPOSED`.
