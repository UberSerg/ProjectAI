# Исполнение


## Визуальный ориентир

![Исполнение](../../_assets/illustrations/prognoz-politika-risk.jpg)

*Адаптер; брокер не в V1. Иллюстрация Vault; не скриншот приёмки.*

**aliases:** Execution  
**Baseline:** `origin/main` `73c2e25e6aed323174b11dea4514946d5897f54b`  
**См.:** [[Shadow-портфель]], [[Исторический симулятор]], [[Торговая политика]], [[Рыночные данные]]

## 1. Назначение

Превратить уже принятое намерение в цену и количество в том контуре, который реально включён: виртуальный Shadow, исторический прогон или исследовательская симуляция. Боевой брокер сюда не входит.

## 2. Какую задачу решает

Сохраняет одну и ту же развилку решения при разных способах «сделки» и не пускает внутридневную котировку в обучение.

## 3. Как работает простыми словами

Политика говорит, какую долю хочет. Исполнение отвечает, сколько лотов можно купить на кэш после комиссии и по какой цене это случилось. Для живого Shadow цена входа — официальное открытие следующей сессии. Для исследовательской экономики доказательств цена тоже OPEN следующего дня, но книга другая и веса дробные.

## 4. Архитектура

Обзор называет целевую цепочку: Order Intent → сменяемый Execution Adapter. Поиск класса с именем `ExecutionAdapter` или `OrderIntent` по `backend/app` на этом SHA совпадений не дал. Роль закрыта конкретными путями, а не одним портом с таким именем. `[GITHUB_VERIFIED]` пустой поиск; формулировка цели — обзор.

Реализованные пути:

| Путь | Где | Цена | Количества |
|---|---|---|---|
| Shadow, история | заполнение по дневной свече | OPEN следующей сессии | V1 мог быть дробным |
| Shadow, live | Redis intraday, флаг выключен по умолчанию | OPEN котировки, не LAST | V2 целые лоты |
| Исторический симулятор | `modules/simulator` | по правилам прогона | по умолчанию дробные, ADR 0008 |
| Evidence economics | `modules/research_evidence` | следующий официальный OPEN | `FRACTIONAL_RESEARCH_WEIGHTS` |
| Тариф брокера | `broker_accounts.py` | не исполняет | только оценка комиссии |

Докстринг брокерского API: «No OAuth / execution / secrets». `[GITHUB_VERIFIED]`

## 5. Поток данных

```text
целевой вес
  → резерв кэша и бюджет комиссии
  → целые продажи, затем покупки (Shadow V2)
  → PENDING
  → OPEN следующей допустимой сессии
  → fill с провененцией
```

LAST обновляет живую пометку и не создаёт fill. Пропущенный OPEN не заменяется close (контракт Evidence и смысл ADR 0007 для Shadow).

Порядок лотов V2: сначала продажи, затем покупки по устойчивому приоритету. Неизвестный размер лота даёт пропуск с причиной. См. [[Shadow-портфель]].

## 6. Что уже реализовано (только подтверждённое)

- Два пути fill Shadow: свечной и `SHADOW_NEXT_SESSION_OPEN_V1` из OPEN в Redis. `[GITHUB_VERIFIED]` ADR 0007.
- Запрет исполнять ордер, созданный после открытия, по уже известному OPEN этой сессии. `[GITHUB_VERIFIED]` ADR 0009.
- Целочисленный денежно-безопасный план V2. `[GITHUB_VERIFIED]` ADR 0008.
- Исследовательский исполнитель Evidence: long-only, без плеча, кэш как класс актива, ребаланс каждые 20 сессий, верхние 20% равным весом, дивиденды не в денежном потоке, семантика `PRICE_RETURN`. Если OPEN нет — `EXECUTION_PRICE_UNAVAILABLE`. Если выход не оценить — `UNRESOLVED_EXIT` и артефакт `PARTIAL`. `[GITHUB_VERIFIED]` документ Evidence Engine.
- Комиссии исследовательского пути — сценарии 0, 10, 30, 50 б.п. на сторону, подпись `ASSUMED_ALL_IN_COST_BPS_PER_SIDE`. Это допущения, не счета брокера. `[GITHUB_VERIFIED]`

## 7. Что частично реализовано

- Адаптер «один интерфейс на все режимы» в обзоре назван целью. Общего класса с таким именем нет.
- Intraday выключен, пока оператор не включит флаг.
- Симулятор не приведён к лотам V2.
- Режим `TOTAL_RETURN_GROSS_V1` в симуляторе ADR 0010 не включает.

## 8. Что пока исследуется

Человеческое подтверждение реальной заявки и ограниченная автономия названы дальним путём в правилах проекта и явно исключены из V1.0 в CHANGELOG. Импорт сделок брокера запрещён решением 2026-11-19. `PROPOSED` не стоит считать дорожной картой к реализации из этого паспорта.

## 9. Технические ограничения

- Исполнение не кормит признаки модели.
- Нельзя исполнить по LAST.
- Нельзя выдумать `lot_size=1`.
- Нельзя провести личную операцию пользователя из Shadow fill.
- Оценка комиссии по тарифу не создаёт ордер.
- Запаздывающее наблюдение OPEN допустимо только если ордер уже существовал до открытия (ADR 0007). Для ордера после открытия это исключение не работает (ADR 0009).

## 10. Известные ошибки

Отсутствие единого класса адаптера — архитектурный пробел относительно текста обзора, не инцидент на проде. Живые пропуски fill на машине владельца этим аудитом не снимались.

## 11. Основные пользовательские сценарии

- На `/shadow` увидеть ордер в ожидании открытия и затем fill.
- В симуляторе смотреть исторический прогон, помня, что лоты могут быть дробными.
- В «Доказательствах» читать исследовательскую экономику с плашкой, что это не боевая торговля.
- Завести тариф в профиле комиссии для оценки личной сделки. Заявка при этом не уходит.

## 12. Тестирование

Тесты не запускались. Контракты fill покрываются тестами Shadow по историческим отчётам CI, не по этому аудиту.

## 13. История развития

Сначала fill ждал дневную свечу и мог висеть в `WAITING_FOR_FUTURE_MARKET_OPEN`, хотя OPEN на ISS уже был. ADR 0007 добавил опциональный intraday-путь. ADR 0008 добавил лоты для новой группы. ADR 0009 закрыл подглядывание в текущий OPEN.

## 14. Потенциальное развитие

Отдельный Simulator Realism с целыми лотами назван в ADR 0008 будущей задачей. Общий Execution Adapter как порт — цель обзора, без задания на код в Master Context. Реальная отправка заявок не авторизована.

## 15. Зависимости

[[Торговая политика]], [[Рыночные данные]], Redis для intraday, [[Риск]] там, где допуск уже вынесен в статус. Не зависит от секретов брокерского кабинета: их в API нет.

## 16. Связанные задачи

Сетевое закрытие опубликованных портов отложено владельцем и не является частью исполнения. PR B меняет превью личной операции, не Shadow fill.
