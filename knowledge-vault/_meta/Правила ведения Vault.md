# Правила ведения Vault

**Версия правил:** 2.0  
**Дата:** 2026-11-23  
**Статус:** LOCAL_ONLY — публикация в Git только по решению Owner

## Назначение

KRAKEN Vault — человекочитаемый слой знаний, истории, проблем, бэклога и планирования.  
Он **не** заменяет:

| Источник | Роль |
|---|---|
| GitHub `UberSerg/ProjectAI` | код, PR, CI, Issues, ADR |
| `docs/development/CHATGPT_MASTER_CONTEXT.md` | проверенный статус проекта |
| `docs/development/KRAKEN_OPERATING_PROTOCOL.md` | операционный протокол |

## Уровни статуса (не синонимы)

1. Реализовано в коде  
2. Проверено тестами  
3. Смержено в `main`  
4. Проверено в работающем приложении  
5. Принято владельцем  
6. Включено в релиз  

В карточках предпочтительно раздельные поля:

```yaml
implementation_status: partial   # none | partial | implemented
test_status: targeted            # none | targeted | ci_green
merge_status: open               # none | open | merged
runtime_status: unverified       # unverified | reported | verified
owner_acceptance: pending        # pending | rejected | accepted
release_status: not_in_release
```

## Уровни доказательности

- `GITHUB_VERIFIED` — независимо подтверждено по GitHub (SHA / PR / CI)
- `REPORTED_BY_CURSOR` — заявлено Cursor, не независимо воспроизведено
- `REPORTED_BY_OWNER` — заявлено Owner (скриншоты, решение)
- `PROPOSED` — план / предложение
- `UNVERIFIED` / `НЕ ПОДТВЕРЖДЕНО` — нет источника

Нельзя повышать `REPORTED_BY_CURSOR` до `GITHUB_VERIFIED` без проверки.

## После значимого изменения

Разработчик / агент проверяет четыре направления:

1. **История** — датированное событие в `04-ИСТОРИЯ РАЗРАБОТКИ`
2. **Система** — паспорт модуля / термин, если поведение изменилось
3. **Проблемы и задачи** — статусы + история переходов
4. **Планирование** — зависимости / ближайший этап, если затронуто

Не дублировать полное описание в шести местах: детали в одной заметке, остальные — ссылки.

## Владение файлами

Один файл одновременно редактирует только один автор/агент.  
Agent 00 назначает владельцев каталогов.  
Конфликтующие правки нельзя молча перезаписывать.

## Запреты

- Секреты, `.env`, токены, персональные ledger/DB dumps
- Объявлять PR смерженным только по заметке Vault
- Выдумывать даты, PR, авторов, результаты тестов
- Автоматически стартовать реализацию backlog
- Публиковать Vault в Git/облако без Owner

## Git (активно)

Vault лежит в **том же** репозитории ProjectAI: каталог `knowledge-vault/`.  
В начале работы — pull чужих правок Vault. После значимого изменения — обновить заметки, commit, push.  
Локальный `E:\kraken Vault` — только junction на `<clone>/knowledge-vault`, не вторая копия.  
См. [[Подготовка к Git]] и `.cursor/rules/45-knowledge-vault.mdc`.
